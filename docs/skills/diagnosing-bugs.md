# 诊断 Bug

> 结构化调试流程，用于排查硬 Bug 和性能回归。

---

## 触发条件

- 用户报告 Bug 但原因不明
- 测试失败且无法一眼定位
- 性能回归需要定位瓶颈
- 生产环境问题排查

---

## 调试循环

严格按以下顺序执行，每一步完成后再进入下一步：

### 1. 复现（Reproduce）

- 获取最小复现步骤
- 确认 Bug 在当前环境可复现
- 记录复现结果到 `docs/bugs/`

```
复现检查清单：
[ ] 有明确的复现步骤
[ ] 在当前环境确实可复现
[ ] 已记录预期行为 vs 实际行为
```

### 2. 缩小范围（Minimise）

- 二分法定位：逐步缩小可疑代码范围
- 隔离依赖：逐一排除外部因素
- 确认最小复现用例

```
缩小范围检查清单：
[ ] 已定位到具体模块/函数
[ ] 已排除外部依赖干扰
[ ] 最小复现用例 < 20 行（理想情况）
```

### 3. 假设（Hypothesise）

**在修改任何代码之前**，先形成明确的假设：

- 你认为根因是什么？
- 为什么这个根因会导致观察到的现象？
- 如果假设正确，修改后应该观察到什么变化？

```
假设模板：
根因：[描述你认为是根本原因的问题]
预期：[修改后应该观察到什么]
```

### 4. 插桩（Instrument）

- 添加临时日志或断言验证假设
- 使用调试器逐步跟踪
- 记录关键变量状态

### 5. 修复（Fix）

- 基于确认的根因进行最小修复
- 先写测试覆盖 Bug 场景
- 修复后运行完整测试套件

### 6. 回归测试（Regression-test）

- 确认修复后 Bug 不再复现
- 运行相关测试套件
- 检查是否引入新问题

---

## 记录规范

Bug 修复完成后，在 `docs/bugs/` 下创建记录：

```markdown
# Bug：[简短描述]

- **发现日期**：YYYY-MM-DD
- **修复日期**：YYYY-MM-DD
- **严重程度**：P0/P1/P2

## 复现步骤
1. ...
2. ...

## 根因
[描述根本原因]

## 修复
[描述修复方案]

## 预防措施
[如何避免同类问题再次出现]
```

---

## 禁止事项

- 禁止在未形成假设前修改代码
- 禁止"试试这个行不行"式的随机尝试
- 禁止跳过复现步骤直接修复
- 修复后必须添加回归测试
