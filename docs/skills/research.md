# 技术调研

> 对照高可信源进行技术调研，将发现记录为带引用的 Markdown 文件存入仓库。

---

## 触发条件

- 需要评估新技术选型
- 需要对比多个方案
- 需要了解某个技术的最佳实践
- 需要验证某个技术假设

---

## 调研流程

### 1. 明确调研问题

```
我要调研什么？
为什么需要这个调研？
决策会影响到什么？
```

### 2. 确定信息源优先级

| 优先级 | 信息源 | 示例 |
|--------|--------|------|
| 🥇 最高 | 官方文档 | 语言/框架官方站点 |
| 🥈 高 | 源代码/Issues | GitHub 仓库 |
| 🥉 中 | 权威博客/文章 | 核心维护者博客 |
| 4️⃣ 低 | 社区讨论 | Stack Overflow、Reddit |
| ❌ 不使用 | 无来源的 AI 训练数据 | 未经证实的信息 |

### 3. 收集证据

每个结论必须附带引用来源：

```markdown
## 结论：PostgreSQL 更适合本项目

**证据**：
- 官方文档：PostgreSQL 17 支持 JSONB 索引（来源：postgresql.org/docs/17）
- 性能测试：百万级数据下查询性能优于 MySQL 30%（来源：benchmark-report-2026）
```

### 4. 组织调研文档

存入 `docs/input/` 或 `docs/discussions/`：

```markdown

## 调研问题
[一句话描述要回答的问题]

[为什么需要做这个调研，背景是什么]

## 方案对比

### 方案 A：[名称]
- **优势**：
- **劣势**：
- **适用场景**：
- **来源**：[引用链接]

### 方案 B：[名称]
- **优势**：
- **劣势**：
- **适用场景**：
- **来源**：[引用链接]

## 推荐方案
[推荐方案及理由]

## 决策影响
- 影响范围：[哪些模块/功能]
- 迁移成本：[如有]
- 风险：[潜在风险]

## 参考来源
1. [来源标题](URL) — 可信度：高/中/低

```

---

## 禁止事项

- 禁止使用无来源的 AI 训练数据作为决策依据
- 禁止只看一篇文档就下结论
- 禁止跳过对比直接选择"最流行"的方案
- 调研文档必须存入仓库，不能只留在聊天里
