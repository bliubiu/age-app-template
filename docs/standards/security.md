# 安全规范

> 合并自 kubet 项目实践和 projInit 通用安全规范。

---

## 加密策略

### 加密算法

| 算法标签 | 加密算法      | 说明           |
| :------- | :------------ | :------------- |
| `0x00`   | AES-256-GCM   | 主选算法       |
| `0x01`   | SM4-GCM-SIV   | 国密合规候选   |

- **国密合规场景**：默认使用 SM4-GCM-SIV
- **非国密场景**：使用 AES-256-GCM

### 密文格式

```
ENC(base64密文)
```

base64 解码后的二进制载荷布局：

```
[算法标签 1字节] + [nonce 12字节] + [ciphertext 密文] + [tag 认证标签 16字节]
```

### 密钥管理

- 首次运行自动生成 32 字节随机密钥，存储到项目安全目录（如 `.{{project}}/key`）
- 密钥文件权限应设为仅所有者可读写（Unix 0600）
- 禁止手工编辑密钥文件
- 密钥获取失败（文件损坏、长度错误）直接报错终止，绝不回退到默认密钥或全零密钥

### 加密实现要求

- 配置文件中密码空字符串使用随机生成强口令方法赋值
- 一次生成严格遵循跨阶段步骤密码口令一致性
- 自动识别加密标识符 `ENC()`，避免循环加密
- 解密时自动读取载荷首字节算法标签，路由到对应算法解密

## 脱敏策略

### 脱敏规则

- **密码**：全部替换为 `*` 号
- **IPv4**：脱敏为 `*.*.1.1`（127.0.0.1、localhost 可保留完整）
- **身份证**：脱敏为 `******************`
- **手机号**：脱敏为 `***********`
- **邮箱**：脱敏为 `****@***.***`

### 脱敏实现

- 识别敏感字段可使用 FSM 状态机，避免使用低效的正则匹配规则
- 日志/报告文件（HTML/Excel）需脱敏，避免敏感数据泄露
- 日志内容不能记录敏感信息，禁止记录：密码、完整身份证号、手机号等

---

## 日志安全

- 日志内容不能记录敏感信息，必须严格遵循脱敏策略
- 禁止记录：密码、完整身份证号、手机号等敏感数据或隐私数据
- 所有错误信息都必须使用中文，禁止打印明文密码等敏感信息

---

## API 安全

- 启用速率限制
- 请求签名验证
- 输入验证与过滤
- 服务间通信的 API 密钥使用短期令牌（如 JWT）或双向 TLS 认证

---

## 依赖安全

- 优先使用较新稳定版本的仓库
- 每月至少更新一次依赖版本，修复已知漏洞
- CI/CD 流水线中集成漏洞扫描（如 `npm audit`、`cargo audit`）

---

## 容器与 K8s 安全

- **镜像安全**：所有镜像必须经过漏洞扫描，禁止使用 latest 标签
- **密钥管理**：
  - 禁止在 ConfigMap 中存储敏感信息
  - 使用 K8s Secrets + 加密工具（Sealed Secrets/Bitnami Secrets）
  - 生产环境密钥定期轮换（建议 30 天）
- **网络策略**：
  - 默认拒绝所有入站/出站流量
  - 按需开放服务间通信
  - 禁止 Pod 直接访问宿主机网络
- **RBAC 权限**：
  - 遵循最小权限原则
  - 服务账号仅授予必要权限
  - 定期审计权限使用情况
- **运行时安全**：
  - Pod 安全上下文：禁止以 root 运行，只读根文件系统
  - 资源隔离：设置 ResourceQuota 和 LimitRange
  - 开启 API Server 审计日志

- ✅ 是否有敏感信息泄露风险？

- ✅ 加密算法是否正确使用？
- ✅ 密钥是否硬编码？
