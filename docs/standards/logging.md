# 日志规范

> 提取自 kubet 项目实践，定义统一的日志格式和管理策略。

---

## 日志级别

| 级别  | 说明                     | 使用场景                       |
| :---- | :----------------------- | :----------------------------- |
| DEBUG | 调试信息                 | 开发环境使用                   |
| INFO  | 常规操作记录             | 关键业务流程节点               |
| WARN  | 预期内异常，不影响核心功能 | 可恢复错误                     |
| ERROR | 预期外错误，需要关注     | 业务异常、外部依赖失败         |
| FATAL | 系统级错误，无法恢复     | 启动失败、数据库连接失败       |

默认日志级别：**ERROR**（可通过配置文件指定）

---

## 日志格式

```
[YYYY-MM-DD HH:MM:SS.SSS] [级别] [线程ID或进程ID] [模块:行号] - 日志内容
```

### 格式说明

- **时间戳**：`YYYY-MM-DD HH:MM:SS.SSS`，本地时间，不含时区
- **级别**：DEBUG / INFO / WARN / ERROR / FATAL
- **线程/进程ID**：用于并发问题排查
- **模块:行号**：精确到源码位置
- **日志内容**：中文描述，清晰记录操作行为、执行结果、错误信息

---

## 日志输出

### 文件输出

- 默认路径：`项目根目录/logs/`
- 文件命名格式：`项目名-YYYYMMDD.log`（如 `project_name-20231225.log`）
- 按日期轮转：每日一个文件
- 保留天数：32 天，自动清理过期日志

### 终端输出

- 同时支持文件输出和终端输出
- 可视化部署进度条展示

---

## 日志内容要求

- 统一使用 UTF-8 编码，中文语言
- 清晰记录操作行为、执行结果、错误信息
- 便于问题排查和审计
- **必须脱敏**：禁止记录密码、完整身份证号、手机号等敏感数据

---

## 日志使用规范

- **DEBUG**：开发调试信息，生产环境默认关闭
- **INFO**：关键业务流程节点（如"用户登录成功"、"订单创建完成"）
- **WARN**：可恢复的异常（如"重试第3次"、"配置项使用默认值"）
- **ERROR**：需要关注的错误（如"数据库连接超时"、"第三方 API 调用失败"）
- **FATAL**：系统级致命错误，记录后退出

---

## 禁止事项

- 禁止记录明文密码
- 禁止记录完整身份证号
- 禁止记录手机号、邮箱地址
- 禁止记录 Token/Secret/Key 等凭证信息
- 禁止在日志中输出完整的敏感请求体
