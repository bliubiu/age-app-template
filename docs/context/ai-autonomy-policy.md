# AI 自主性策略

> 定义 AI 在项目中的自主决策边界。

---

## 自主性等级

### 🟢 完全自主（无需确认）

- 代码风格和格式修正
- 按现有模式添加单元测试
- 修复编译错误/类型错误
- 按现有约定添加日志
- 更新 CHANGELOG
- 按 docs/standards/ 规范执行标准操作

### 🟡 建议后执行（可自主但有风险提示）

- 引入新的第三方依赖
- 修改已有接口签名
- 重构超过 50 行的函数
- 修改数据库迁移脚本
- 修改配置文件

### 🔴 必须确认（需用户批准）

- 删除或大规模重写已有功能
- 修改认证/授权逻辑
- 修改加密/安全相关代码
- 数据库 Schema 变更
- 部署配置变更
- 引入新的架构模式
- 修改 docs/architecture/ 或 docs/design/ 中的稳定文档

---

## Plan 触发规则

### 必须写 Plan

- 变更 API、数据库/模型、认证、集成、部署
- 跨多个功能面变更用户可见行为
- 涉及多个模块、改变共享行为
- 预计超过一个 AI Session
- 需要分阶段执行或显式闭包门
- 存在未解决的产品/技术风险

### 可以跳过 Plan

- 文案修改、小型样式调整
- 纯测试代码清理
- 单文件修复且有明确测试覆盖
- 低风险本地编辑

---

## 代码审查触发规则

| 变更类型       | 是否需要独立审查 |
| :------------- | :--------------- |
| 核心业务逻辑   | ✅ 必须          |
| 安全相关代码   | ✅ 必须          |
| 数据库 Schema  | ✅ 必须          |
| API 接口变更   | ✅ 必须          |
| 工具函数       | ⚪ 可选          |
| 样式/文案      | ❌ 不需要        |
| 测试代码       | ❌ 不需要        |

---

## 错误处理策略

- 遇到不确定的决策 → 写 `docs/discussions/` 记录歧义点
- 连续 3 次同一问题 → 创建 `docs/bugs/` 记录
- 发现文档过时 → 标记并报告，不能沉默
