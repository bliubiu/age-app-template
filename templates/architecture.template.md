## 设计原则

本架构遵循以下核心原则：

1. **单一职责**：每个模块只做一件事
2. **依赖倒置**：高层模块不依赖低层模块
3. **接口隔离**：最小化模块间耦合
4. **可测试性**：每个模块可独立测试
5. **渐进式演进**：架构允许未来扩展

### 核心业务流程

#### [流程 1 名称，例如：用户注册]

```
用户        边界层       应用层       领域层       基础设施
 │─请求──▶│           │           │           │
 │         │─认证──▶  │           │           │
 │         │          │─创建聚合根──▶│          │
 │         │          │           │─保存────▶ │
 │         │          │           │           │
 │◀──响应──│◀──结果──│◀──领域事件────│◀──存储──│
```

**时序说明**：
1. 用户向 `/api/register` 发送 POST 请求
2. BFF 层完成认证和参数校验
3. 应用服务调用领域层创建用户聚合根
4. 领域层通过 Repository 接口持久化
5. 基础设施层执行数据库写入
6. 结果沿路径反向返回
